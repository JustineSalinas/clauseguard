# Civil Code provisions

**Owner:** Salinas
**Task:** T8

## Source and scope

Verbatim text of Republic Act No. 386 (the Civil Code of the Philippines),
scraped directly from the official text hosted at lawphil.net
(`https://lawphil.net/statutes/repacts/ra1949/ra_386_1949.html`) and parsed
article-by-article with a script, not summarized by a model — grounding a
legal risk claim in paraphrased text would defeat the point of grounding at
all.

Not the full 2,270-article Code. Scoped to the provisions actually relevant
to freelance/consulting contracts, matching `lib/pipeline/taxonomy.ts`:

- **Articles 19–21** (Human Relations) — abuse of right, bad-faith injury
- **Articles 1156–1422** (Obligations and Contracts, Book IV Titles I–II) —
  mutuality, consent, void/voidable contracts, the bulk of what a clause
  grounds against
- **Articles 2195–2235** (Damages, Book IV Title XVIII)

310 articles total. `data/provisions.json`.

## Chunking strategy

One article = one chunk. The Code's own article boundaries are already the
right granularity for retrieval: each one is a self-contained legal rule,
short enough to embed whole (no article here exceeds ~400 words), and long
enough to carry its own meaning without surrounding context. No
sub-article splitting, no merging of adjacent articles — a merged chunk would
retrieve as "close enough" to two different legal questions and ground
neither precisely.

Each record:
```json
{
  "code": "CIVIL",
  "article": "1308",
  "heading": null,
  "text": "The contract must bind both contracting parties..."
}
```

`heading` is null throughout — lawphil's Civil Code text doesn't carry
short per-article titles the way the Labor Code source does (compare
`corpus/labor-code/`). The article number plus text is unambiguous on its
own for this Code.

## Loading

`npm run seed:corpus` runs `scripts/seed-corpus.ts`, which upserts both
`data/provisions.json` files into `public.provisions` via the service role
key (`code, article` is the unique constraint — safe to re-run).
**Embeddings are not generated by this script.** The `rag` grounding arm
needs the `embedding vector(768)` column populated separately once the Day 9
embedding model decision is finalized — see `lib/pipeline/ground/README.md`.
The `static` arm (`provision_mappings`) is fully usable as soon as this
script has run once.
